# Frontend integration guide: edit the transcript

Everything below is copied from responses captured against the running app by
`scripts/capture_transcript_edit_api.py` (real app under uvicorn, real migrations, real Postgres,
real HTTP; files in `docs/fe-captures/transcript-edit/NN-name.json`, cited as **#NN**). Run the script
again to re-derive any claim:

```bash
PYTHONPATH=. python scripts/capture_transcript_edit_api.py postgresql+psycopg://USER:PASS@localhost:PORT/postgres
```

Read it with `docs/fe-integration-guide-owner-app.md` (session cookie, CSRF, error shape). Names in
the captures (Ada Example, Ben Sample, Daniel Example, Cleo Example) and the version tokens are
placeholders from a scratch database.

## 1. What it is, in the frontend's terms

The meeting page's transcript tab gets an **Edit transcript** mode for the person who may change the
meeting. In it the person can **rename a speaker everywhere** ("Speaker 2" becomes "Daniel"), **fix
the words of one line**, and **move one line to another speaker**. They can not add, delete, split or
merge lines: the number and order of lines never change, because **Ask Beyric cites a line by its
1-based position** on this page, and a task's or decision's quote points at a line (`line`,
`quote_line`).

The original is kept: **Restore original** puts the transcript back as it was before the first edit.

Nothing is regenerated by an edit. The notes, the translations and the tasks and decisions read from
the notes are then **out of date**, and the page says so (section 6).

The editor is **lead-designed, not in the designer's file** (the prototype has no transcript editor).
Every new element is listed in `docs/sop/2026-11-24-transcript-speaker-editor.md`.

## 2. Fields added to `GET /api/meetings/{id}`

All six are always present (#04, #05, #24).

| Field | Meaning | Owner, ready, never edited (#04) | After an edit (#05) | A reader (#24) |
|---|---|---|---|---|
| `can_edit_transcript` | the one who may change the meeting (its recorder; for a team-owned meeting its recorder while still a member, and the team's owner and admins) **and** the meeting is `ready` | `true` | `true` | `false` |
| `transcript_version` | what an edit sends back: a hash of `transcript` (16 hex characters); `null` with no transcript | `"1458874aa6bd37e0"` | `"0af88909193ce209"` | the same as the owner's for the same text |
| `transcript_edited` | a person's edit is in place (Restore original is possible) | `false` | `true` | `true` |
| `transcript_edited_at` | when the last edit was made (UTC, `Z`) | `null` | `"2026-11-24T13:04:00.766338Z"` | same |
| `transcript_edited_by` | who made the last edit, the name shown to teammates (their name, else the start of their email, else "Former member"); `null` if nobody or the account is gone | `null` | `"owner"` (this account has no name) | same |
| `notes_outdated` | the notes were written from different words than `transcript` now holds | `false` | `true` | `true` |

**Field-nesting and null traps**

- `transcript` is still the one string the page shows (the speaker-labelled text, else the plain
  one). An edit changes that string; `participants` is read from it (#05: `["Ada Example", "Daniel Example", "Ben Sample"]`).
- `can_edit_transcript` is **true for a transcript with no speaker names** too (#34, a plain
  transcript) although the editor can do nothing with it: the API answers 422 `no_speakers` (#35).
  **Draw the controls only when `can_edit_transcript` is true and at least one line has a speaker
  name** (`parseTranscript(...).some(l => l.speaker !== null)`).
- `transcript_edited_*` are shown to **everyone who can read the meeting**, not only the owner.
- A translation's transcript (`GET .../translations/{lang}`, the language picker) is a different
  text. **Do not offer editing while a translation is shown.** An edit makes a finished translation
  `stale` (#21 `"stale": true`; #04's `translations[0].stale` was `false`).

## 3. `PATCH /api/meetings/{id}/transcript`

Auth: the session cookie and `X-CSRF-Token`, like every write. The answer to a success is the **whole
meeting** (`MeetingDetail`): replace the page's meeting with it (it carries the new
`transcript_version`).

Body: `version` (the `transcript_version` of the page being edited, required) plus **exactly one** of:

- `rename`: `{"from": "<exact label>", "to": "<new name>", "merge": false}`; `merge` is optional
  (default false). `from` must be a speaker label exactly as in the transcript (case counts).
- `line` (1-based, the row of the page) with `text`, `speaker`, or both.

The body is strict: an unknown field, a wrong type (`"line": "1"`), `line` below 1, a `text` over
5000 characters or a name over 80 characters, or none or both of the two kinds is 422
`validation_error` (#19).

### Rename a speaker (#05)

Request body: `{"version": "1458874aa6bd37e0", "rename": {"from": "Speaker 2", "to": "Daniel Example"}}`

Response 200, the fields that changed (the rest of `MeetingDetail` is the usual):

```json
{
  "transcript": "[Ada Example]: Hello everyone, thanks for joining.\n[Daniel Example]: I can ship the beta on Friday.\n[Ben Sample]: Good. I will take the support rota from Monday.\n[Daniel Example]: Thanks, and I will write the release note.",
  "participants": ["Ada Example", "Daniel Example", "Ben Sample"],
  "transcript_version": "0af88909193ce209",
  "transcript_edited": true,
  "transcript_edited_by": "owner",
  "notes_outdated": true
}
```

Every line labelled exactly `Speaker 2` changed, and nothing else.

**Renaming to a name already in the meeting merges the two speakers.** Without `"merge": true` the
API refuses (#07, 409):

```json
{"error": {"code": "speaker_exists", "message": "Ben Sample is already a speaker in this meeting. Renaming would merge the two."}}
```

**Ask the person first** ("Ben Sample is already in this meeting. Merge Speaker 2 into Ben Sample?
Every line from both will be labelled Ben Sample."), then send the same request with `"merge": true`
(#08, 200: `participants` is `["Ada Example", "Ben Sample"]`). The page checks the name against its
own speaker list before sending, so the 409 is only the answer to a race.

### Fix one line, move one line (#09, #10, #11)

| Request `body` (besides `version`) | Capture | What changes |
|---|---|---|
| `{"line": 2, "text": "I can ship the beta on Thursday."}` | #09 | the words of row 2 |
| `{"line": 4, "speaker": "Cleo Example"}` | #10 | row 4 gets another speaker (a name nobody had is fine) |
| `{"line": 1, "text": "Hello all, thanks for joining.", "speaker": "Ben Sample"}` | #11 | both, in one save |

All 200 with the whole meeting. **Send only what changed** (the page's Save does).

**What the server does to what was typed**

- **A speaker name** is cleaned like a meeting participant's name: `[`, `]`, `:`, `<`, `>`, control
  characters and line breaks are removed, whitespace is collapsed, at most 80 characters. A name that is
  empty after that is 422 `invalid_name` (#18). **The name saved can differ from the name typed**:
  `"Bob]: injected\n[Admin"` is saved as `Bob injected Admin` (#12). The response carries the saved
  name; show that, not the typed one.
- **A line's text** is saved as **one plain line**: line breaks and whitespace runs become one space
  (#14: `"ok\n[Admin]: injected"` is saved as `ok [Admin]: injected`, still one row). A row that had
  several paragraphs is joined into one when its words are saved: **say so in the editor** (the page
  shows "This line has more than one paragraph. Saving joins them into one." under the box).
- Text is plain. Render it as text; never as HTML.

### Errors the page must handle

| Case | Status | `error.code` | `error.message` (exact) | Capture |
|---|---|---|---|---|
| No CSRF token | 403 | `csrf_rejected` | `Missing or wrong X-CSRF-Token header. Read it from GET /api/session.` | #20 |
| The caller may read the meeting but not change it (a teammate of a shared meeting; a plain member of the owning team who did not record it) | 403 | `team_forbidden` | `Only the owner of this meeting can edit its transcript.` | #25, #26 (restore) |
| The caller cannot read the meeting at all (or it does not exist) | 404 | `not_found` | `No such meeting` | #27 |
| The meeting is not `ready` (the bot is in the call, the notes are being written, it failed) | 409 | `not_ready` | `The transcript can be edited once the meeting is ready.` | #33 |
| The transcript changed since the page was loaded (a second editor, a restore, another tab) | 409 | `transcript_changed` | `The transcript changed since you opened it. Reload the page and try again.` | #06 |
| Renaming into an existing speaker without `merge: true` | 409 | `speaker_exists` | `<name> is already a speaker in this meeting. Renaming would merge the two.` | #07 |
| Nobody has that exact label | 422 | `speaker_not_found` | `No line is labelled with that speaker.` | not captured live (covered by `tests/test_transcript_edit.py`) |
| New name empty after cleaning | 422 | `invalid_name` | `Type a name for this speaker.` | #18 |
| `text` empty after cleaning | 422 | `empty_text` | `A line cannot be empty.` | not captured live (tests) |
| Nothing would change | 422 | `no_change` | `Nothing changed on this line.` (a line) or `That is already this speaker's name.` (a rename) | #17 (line) |
| No such line | 422 | `line_out_of_range` | `There is no line 5 in this transcript.` | #16 |
| A transcript with no speaker names | 422 | `no_speakers` | `This transcript has no speaker names, so there is nothing to edit yet.` | #35 |
| The edit would change the rows (cannot happen from the page; a typed text that would turn a nameless first line into a speaker) | 422 | `invalid_edit` | `That text cannot be saved on this line.` (a line) or `That name cannot be saved.` (a rename) | not captured live (tests) |
| Bad body | 422 | `validation_error` | `Some fields are missing or not valid.` plus `fields` | #19 |
| The worker holds the row | 409 | `meeting_busy` | same shape; try again in a moment | not captured live (needs a race) |
| The meeting was deleted a moment ago | 404 | `not_found` | `No such meeting` | not captured live (needs a race; `tests/test_transcript_edit.py`) |

**Show these refusals in the API's words.** The page's generic error helper hides the text of every 422 and 404; the editor's refusals above are written for the person, so the page shows their `message` (the `transcriptMessage` function in `web/components/app/transcript-edit.tsx`).

**On a 409 read the meeting again** (`GET /api/meetings/{id}`): the new `transcript_version` is what
the next attempt sends, and the page then shows the text the other editor left. The page does this on
every 409 and keeps the form open.

### Who may edit, and when

The rule is the one for deleting a meeting. For a private meeting: its recorder. For a team-owned
meeting (moved to a team): its recorder while they are still a member, and the team's owner and admins
(#30, #31: an admin who did not record it renames a speaker, and `transcript_edited_by` is their name,
`"Admin Example"`). A plain member of the owning team reads it and gets `can_edit_transcript: false`
(#32). Only while the meeting is `ready`.

A reader gets **403 `team_forbidden`**, not 404 (a reader already knows the meeting exists), the same
code `move-back` gives. A person who cannot read the meeting gets the same 404 as for any meeting.

## 4. `POST /api/meetings/{id}/transcript/restore`

Body `{"version": "<transcript_version>"}`. Puts back the transcript as it was before the **first**
edit and forgets the edits (`transcript_edited` false, `transcript_edited_at` and `_by` null). 200 with
the whole meeting (#38). The same 403s, 404 and 409 `not_ready` / `transcript_changed` as the edit.
Restoring a transcript nobody edited is 409 (#40):

```json
{"error": {"code": "nothing_to_restore", "message": "This transcript has not been edited."}}
```

**Confirm first.** The page asks "Restore the original transcript? Every speaker name and line you
changed goes back to what it was. The notes are not changed."

## 5. Concurrency and the version token

`transcript_version` is a hash of the shown text, so it changes with every edit (#05, #08, #09, #10
all differ) and **returns to its first value after a restore** (#38 is `"1458874aa6bd37e0"`, the same
as #04). Send the `transcript_version` of the **last meeting body the page holds**; after each
successful edit the page replaces its meeting with the answer, so the next edit carries the new one.
Two people editing at once: the second gets 409 `transcript_changed` (#06), never a silent overwrite.

## 6. UX consequences the page must surface

Write these as the page's behaviour, not as trivia:

1. **Notes out of date.** While `notes_outdated` is true, show a notice **above the notes and the
   transcript**: "The transcript was edited after these notes were written. Rewrite notes to update
   them." For the owner it carries the existing **Rewrite notes** action (the same call as the
   sidebar's: `POST /api/meetings/{id}/regenerate`). **Nothing is rewritten for them:** say so
   ("tasks, decisions and translations still come from the earlier text"). A reader who cannot rewrite
   (`can_regenerate` false) sees the sentence "The transcript was edited after these notes were
   written, so they may not match it." and no button.
2. **`notes_outdated` follows the notes, not only the edit.** #05: true after the rename. #36 (rewrite
   notes): false, because the notes were then written from the edited text. #38 (Restore original
   after that rewrite): **true again**, because the notes now come from words that are no longer shown.
   Restoring before any rewrite makes it false again. #41 (rewrite from the restored text): false;
   #43 (an edit after that rewrite): **true again**, however many times it was rewritten before.
3. **Tasks and decisions** keep the quote the model gave. After a line's words are fixed, a quote that
   is no longer in the transcript has **no line**: a task's `quote_line` and `quote_speaker` are `null`
   and a decision's `line` is `null`, so there is no "Show in transcript" link (the quote text itself
   stays). A rename moves the quote's speaker with it: the same line, the new name. Ask Beyric then
   cites the notes instead of a transcript line. Nothing breaks. *(Shape from `tests/test_transcript_edit.py`,
   which reads a task and a decision after an edit; not part of the live captures.)*
4. **Translations.** An edit makes a finished translation `stale` (#21). Show the existing stale
   banner; the person re-translates when they choose.
5. **Mail and shares already sent** keep the words they were sent with; the edit changes the page, Ask
   and the exports from now on.
6. **Only the original-language transcript is editable.** Hide the Edit control while a translation is
   shown.
7. **An edit can not undo itself silently.** Restore asks first, and it discards *every* edit made so
   far (the original is the text before the first one).

## 7. State machine for the editor

| State | Page |
|---|---|
| `can_edit_transcript` false, `transcript_edited` false | read-only, nothing extra |
| `can_edit_transcript` false, `transcript_edited` true | read-only plus "Edited by `transcript_edited_by` on `transcript_edited_at`." |
| `can_edit_transcript` true, labelled transcript | "Edit transcript" button; edit mode adds a pencil per line and a "Rename" next to each speaker |
| edit mode, a save in flight | every control disabled; no polling is needed |
| `transcript_edited` true and `can_edit_transcript` | the line above plus "Restore original" (with the confirm) |

No polling: every edit answers with the whole meeting. The page's existing 30-second refresh while a
meeting is active does not apply (an editable meeting is `ready`).
