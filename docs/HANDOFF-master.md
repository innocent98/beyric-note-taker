## 7. How we work here

- Branch from `main`, PR, CI green, merge on his word with `gh pr merge N --squash --delete-branch`. After a merge, `ci` then `deploy` run; verify `ssh haven-respite 'cd /opt/beyric-note-taker && git rev-parse --short HEAD && docker compose ps --format "{{.Service}} {{.Status}}"' </dev/null` and `curl -s -o /dev/null -w "%{http_code}" https://notes.beyrictech.com/health`. The allow rules are exact-match: use these strings unchanged.
- **The active-meetings count (he runs it, pastes the number):**
  `ssh haven-respite 'cd /opt/beyric-note-taker && docker compose exec -T db sh -c "psql -U \$POSTGRES_USER -d \$POSTGRES_DB -t"' <<< "select count(*) from meetings where status in ('bot_sent','processing');"`
- Conflict churn: parallel sessions edit the Settings page, Meetings page, the checklist, `docs/openapi.json` and `web/lib/api/schema.d.ts`: regenerate with `scripts/export_openapi.py` and `npm run gen:api`, keep both sides of docs. Alembic: check `alembic heads`, renumber at rebase.
- Briefs to sub-sessions (when he allows new ones) must say: run the touched tests plus the whole `tests/test_accounts.py`, the route enumeration test and the OpenAPI tests BEFORE pushing; no AI attribution; push `HEAD:<prefix>/<slug>`; do not merge; "Server steps before merge"; own Postgres container name and port (54311 to 54322 used; next 54323; a Homebrew Postgres works if Docker's disk is full); the UI parity rule; poll CI in the same turn; report in about 12 lines.
- Python checks: `.venv/bin/ruff check .`, `.venv/bin/ruff format --check .`, pytest for touched files; web: `npm run lint`, `npm run typecheck`, `npx vitest run` in `web/`.
- Reading what Vexa's bot saw: its log and screenshots are inside the containers (`vexa-storage:/srv/vexa-storage/data/vexa/signal/1/<meeting id>/botlog.txt`; `vexa:/app/storage/screenshots/`). If a deploy leaves the site down: `docker compose ps -a`, `docker compose logs --tail=30 web` (allow-listed); `next` waits for `web` to be healthy; `deploy.sh` rolls back by itself. Anything needing `sudo` or a restart goes to him as one copy-paste block.
- CSP: FastAPI's is `'self'` only; Next's is nonce-based (`web/proxy.ts`); never touch the CSP header on proxied FastAPI responses.
