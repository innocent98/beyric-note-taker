# UI audit: the designer's NEW main app file against the old file and the live app (`main` 9ddf15f)

Read-only audit, 2026-11-07 (evening). Design file: `docs/ui/Beyric Note Taker redesign/Beyric Note Taker.dc.html`, now 2321 lines (template L9-1311, script L1311-end). The old copy is `git show 0ce3dbc:"docs/ui/Beyric Note Taker redesign/Beyric Note Taker.dc.html"` (2028 lines, PR #80). I read the whole new file (template and script) and the full line diff between the two (474 diff lines, 20 hunks). `D:` is a line in the NEW design file; `W:` is `web/`. Model for the format: `docs/ui/audit-2026-11-07-app.md` (rows there are called A1 to A71; the rows here are B1 onward, so the two never clash). Nothing in the app was changed.

## Read this first (the five findings that matter)

1. **Two things the brief expected to be new are NOT new, and are already built.** The Review screen (loading, failed with "Try again", "Nothing to review yet.", "Not now", "Rewrite notes", "Dismiss", "Remove from list", "All caught up", per-row errors) and the Settings Time zone card ("Use my device") are **identical** in the old and the new file: no diff hunk touches D:874-935 or D:524-545. They are live (audit rows A38, A48 to A51; SOP `docs/sop/2026-11-05-decisions-review-states-and-time-zone.md`). The Decisions loading, failed and empty states are also unchanged and built. "Suggested tasks", "Show source" and "Accept" are **not on Review**: they are on the **Tasks** screen (D:996-1020).
2. **The new file is about one idea: "trust and evidence".** Almost every new thing is a *source line from the transcript* (who said it, at what time, the words) plus a *"Show in transcript"* jump that highlights that row. **We do not store the time of a turn** (A18; `docs/sop/2026-11-04-w7-translate.md:46,77`; the notes code keeps only speaker and text: `app/notes.py:159` `_clean_segments`) **and the transcript is one string** with `[Name]:` lines (`web/lib/transcript.ts`). So "Show in transcript", every Ask Beyric citation chip ("Meeting title · 04:38") and the evidence card on Suggested tasks and Decisions have no honest data behind the time. Cheapest honest route: find the verified quote inside the transcript text (every task `quote` is already checked to be in the transcript, `app/extraction.py:236`) and highlight that line without a time; the time needs a backend change. A decision for Adebayo and the designer.
3. **The AI model already returns half of "Suggested tasks", and we throw it away.** The extraction call asks for `confidence: high | medium | low` per action item (`app/extraction.py:468,506`, `ModelAction.confidence` L176, `CheckedAction.confidence` L204), but no column stores it (`app/models.py` `Task` has none; `grep confidence alembic/` finds nothing). The design's "Medium confidence" / "Low confidence" pill, the "reason" line, the To confirm list and the "Ask before adding unclear tasks" switch all hang on this. It needs one migration (a `suggested` flag, the confidence, a reason text) and a prompt change (reason is not asked today), then the Tasks board, the counts and the mail must ignore suggested tasks (seven places in the design's script exclude them: D:1793, 1828, 2047, 2052, 2057, 2074, 2096).
4. **Decisions grew from a flat list into a tracked record, and the data model has none of it.** New: a status (Approved, Proposed, Replaced, Rejected), "Decided by", "Revisit on", "Replaced by / Replaces", related tasks, evidence. Our `decisions` table is `id, meeting_id, text, position, fingerprint, hidden_at, created_at` (`app/models.py:740-757`), parsed from the notes by code with **no model call** (`app/workspace.py`), and `GET /api/decisions` returns `{id, text}` per decision (`app/api_schemas.py:496`). Everything above needs a migration, an extraction step (a model call, which the AI workspace spec chose to avoid) and a write endpoint (change status, set the revisit date). The only part that is front end today: the tab strip and the row look, filled by one status.
5. **Ask Beyric has no backend of any kind.** No endpoint, no table, no search index (no embeddings or vector search anywhere: `grep -rn "pgvector\|embedding" app alembic` finds nothing). It is also **not in the AI workspace spec** (`docs/superpowers/specs/2026-11-03-ai-workspace-design.md`, whose core rule is "parse what the user already sees, never invent a second opinion"; the spec says Decisions, Review, Tasks, Series are code-parsed with one grounded extraction call per meeting). A question-answering feature is a model call **per question**. The designer drew it as if free. This needs a spec before any build (open questions at the end).

The rest of the file is a front-end job (score tiles on the Series page, overdue wording, the navigation item) once the data exists.

## Questions for the Ask Beyric spec (for the brainstorming with Adebayo; I did not write the spec)

1. **What does it search?** The file says "{N} meetings, {N} decisions and {N} tasks" (D:1912). Is it the notes, the transcripts, or both? Open questions, review items and series agendas are not in that list. Does it read the **transcript** (precise quotes, big) or only the notes, decisions and tasks already extracted (small, cheap, already scoped)?
2. **How does it retrieve?** Today there is no search index. Options: (a) Postgres full-text search plus the extracted tables, no new infrastructure, (b) embeddings (a new extension or service, a cost of its own, a backfill job over every meeting), (c) send everything recent to the model (simple, expensive, a hard size limit). The deployment is a shared VPS (`beyric-note-taker-server` memory): the choice must fit its limits.
3. **Model cost per question.** Every question is at least one model call (the notes, extract and translate calls are once per meeting). Needs: which model, a token budget per question, a daily or monthly cap per person and per workspace, whether it counts against the pilot's hours cap, and a new `ai_runs` kind `ask` so the cost ledger sees it. The designer's "Ask" button looks free. Is the per-question cost acceptable? (HANDOFF section 5 already asks him this.)
4. **Visibility.** Answers must follow `app/visibility.py`: own meetings plus meetings shared with the team; a private meeting of a teammate must never leak into an answer, and a **citation** to a meeting the asker may not read must not exist. What about tasks shown to a person who was assigned a task from a private meeting (they see the quote only: spec 8.2)? Must the retrieval filter first and only then call the model (yes), and how is that tested?
5. **Grounding and citations.** The promise is "Every answer links to the moment it came from". The model must return only cites that exist in what it was given; code must verify each cite (the same rule as `Task.quote`). That requires a place to point: a time per turn (not stored) or a quote search inside the transcript. Is a cite without a time acceptable?
6. **"I could not find that"** versus a wrong answer: the threshold, and the line for a model failure (U2).
7. **Memory and privacy.** Are questions and answers stored? For how long, per person, deleted with the account (`app/deletion.py`)? Do the privacy and terms pages need a line about sending meeting text to the model again, per question? (Terms and privacy changes are covered by his no-notice rule.)
8. **Abuse and injection.** A transcript can contain "ignore your instructions". Answers must treat meeting text as data (as `app/extraction.py` and `app/notes.py` do); Opus review.
9. **What does "Keeps coming up" compute from?** The definition in the file: "Topics discussed in more than one meeting without a decision." Needs: the unit (a topic: a model-made label, or a repeated notes bullet?), the scope (the meetings of one series only, as it sits on the Series page, or all meetings?), how "without a decision" is judged (no decision bullet that mentions it? with the new Decisions status, no Approved decision?), a threshold (2 meetings? 3?), and when it is computed (after each meeting, in the worker, so a page load costs nothing: like `extraction`). The three sample sub-lines differ ("without a decision", "still no owner or date", "approval rules not final"), so they are three kinds of reason, not one count.
10. **What does "Suggested agenda" compute from?** The file lists four sources: repeat topics (B19), overdue work (computed), open questions carried over (exists), tasks to confirm (B21). Is the sentence for each ("Decide the pricing model") written by a model or a template? Does it need a model at all, or only a template over data we have (the three non-topic lines are already pure counts)?
11. **Order of build.** Adebayo asked for his say on which of the three comes first. Cost and dependency say: Suggested tasks (the model already returns confidence) and the Decisions record need the extraction changes and a migration; Suggested agenda and Keeps coming up depend on them; Ask Beyric depends on all of the data and on the largest open questions (1 to 8). A possible sequence: the FE-only pieces first, then Suggested tasks, then Decisions, then Keeps coming up and Suggested agenda, then Ask Beyric. His call.
