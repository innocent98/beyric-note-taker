# SOP: Web pages (Task 6)

## What shipped
The owner's phone-friendly app: login, paste a meeting link, read notes and transcript, rewrite notes, retry failures, manage templates and vocabulary. Plus a `web` service in `compose.yaml`. Commit: `feat: add meeting web pages`.

## Why
The owner needs one place to send the bot and read results. Single owner, no signup.

## How
- **Auth** (`app/auth.py`): password checked with `hmac.compare_digest`; session cookie is HMAC-SHA256 signed with `session_secret` (no extra dependency), HttpOnly, SameSite=Lax, Secure when `cookie_secure` (default true). Login issues a fresh session (no fixation). 5 failed logins per client in 15 min -> 429 (in memory; resets on restart). `create_app` raises in `app_env=production` if `owner_password` or `session_secret` is empty.
- **CSRF**: one app-wide dependency (`auth.guard`) requires login for everything except `/login` and `/health`, and a matching `csrf_token` form field on every POST (403 otherwise). Anonymous sessions carry a token so the login form is protected too.
- **Untrusted text**: Jinja autoescape; notes rendered with markdown-it-py (`commonmark`, `html: False`, images disabled, links get `rel="noopener noreferrer nofollow"`; `javascript:` links are not rendered). CSP is `default-src 'none'` with only same-origin script/style/img, no inline code, so a miss in escaping still cannot run script or load remote images.
- **Statuses**: `bot_sent` = "Bot sent"; `processing` = step in plain words; `failed` shows `failure_reason`. The word "recording" is never shown from status. Meeting URLs (Zoom links carry a password) are never rendered or put in query strings; pages show platform + meeting id.
- **New meeting** (`POST /meetings`): `parse_meeting_url`, then a Postgres advisory lock around "no `bot_sent`/`processing` meeting" + `send_bot` + insert, so a double click cannot send two bots. Vexa failure saves nothing and shows a fixed message (no exception text).
- **Regenerate**: ready meetings only; `generate_notes` from the saved speaker transcript, in the request, no transcription. On failure the old notes are kept.
- **Retry** (`POST /meetings/{id}/retry`): failed meetings only; sets `processing`, keeps `step`, clears `failure_reason`. Refused when `step == waiting` (the bot never captured anything) or when the audio is deleted and no transcript was saved; the page says so.
- **Templates / vocabulary**: list/add/edit and list/add/delete. Term rules match `app/transcribe.py` (no `<`, `>`, newlines; non-empty; at most 100 chars as in `app/notes.py`); duplicates give a clear error. Template instructions capped at 4000 chars (our choice).
- **Pages**: meta refresh every 30 s until `ready`/`failed`; copy buttons (`app/static/app.js`, same-origin, falls back to `execCommand`); small system-font CSS, dark mode via `prefers-color-scheme`.

## What's involved
`app/main.py` (`create_app`, headers, `/health`), `app/auth.py`, `app/web.py`, `app/templates/*.html`, `app/static/app.{css,js}`, `app/config.py` (`app_env`, `cookie_secure`), `pyproject.toml` (markdown-it-py; ruff B008 allowance for FastAPI), `Dockerfile` (`app` user), `compose.yaml` (`web`), `.env.example`, `tests/test_web.py`.

## Verification
`tests/test_web.py` (41 tests, real Postgres, fake Vexa/OpenAI). Run locally against a scratch DB and checked at 375 px in the built-in browser: login, list, ready and failed meeting pages, templates, vocabulary all fit with no horizontal scroll. Not verified: copy buttons in a real browser clipboard, the Docker image/healthcheck (not built), HTTPS Secure cookie end to end.

## Operate / roll back
`docker compose up -d web` (serves on `127.0.0.1:8000`; put a TLS reverse proxy in front). `.env` needs `OWNER_PASSWORD` and `SESSION_SECRET`, or the service exits at start. Over plain http locally set `APP_ENV=development COOKIE_SECURE=false`. Run as `python -m uvicorn app.main:create_app --factory`. Roll back by reverting the commit; no migration.
