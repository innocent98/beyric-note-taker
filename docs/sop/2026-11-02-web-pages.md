# SOP: Web pages (Task 6)

> **Update 2026-11-03:** the `TRUSTED_PROXY_IPS` / `--proxy-headers` approach below was replaced by an edge secret and the setting was removed; see `docs/sop/2026-11-03-edge-secret-and-login-limits.md`. The login limits are now 5 per 5 minutes per address and 10 per hour per account.

## What shipped
The owner's phone-friendly app: login, paste a meeting link, read notes and transcript, rewrite notes, retry failures, manage templates and vocabulary. Plus a `web` service in `compose.yaml`. Commit: `feat: add meeting web pages`.

## Why
The owner needs one place to send the bot and read results. Single owner, no signup.

## How
- **Auth** (`app/auth.py`; **superseded for login and cookies by `2026-11-03-pilot-accounts-core.md`**): password checked with `hmac.compare_digest` on bytes (non-ASCII input is a normal failure, never a 500). `create_app` fails closed: only `app_env` of `development` or `test` may start without secrets; `production` needs a non-empty `owner_password` and `session_secret`; any other value (e.g. `prod`) refuses to start. An empty password never matches, even in dev.
- **Sessions and revocation** (**superseded**: the cookie is now `{uid, csrf, iat, epoch, gepoch}` and the key comes from `session_secret` alone): the cookie is `{auth, csrf, iat, epoch}` signed with HMAC-SHA256 under a key derived from `session_secret` AND `owner_password`, so changing either signs everyone out. `epoch` is compared with `app_state.session_epoch` (table from migration `0002_app_state`, one seeded row) on every logged-in request; `POST /logout` increments it, which revokes every session including copied cookies (single owner, so "log out" means "log out everywhere"). Login issues a fresh token stamped with the current epoch. Cookie is HttpOnly, SameSite=Lax, Secure when `cookie_secure`.
- **Login limit**: 5 attempts per client in 15 min, counted before the password is checked under a lock (parallel requests cannot all slip through) and cleared on success; expired entries are pruned. Client = peer address. `web` runs uvicorn with `--proxy-headers --forwarded-allow-ips=${TRUSTED_PROXY_IPS:-}`: no proxy is trusted by default; Task 7 sets the proxy address and makes nginx overwrite `X-Forwarded-For`.
- **Repeat links**: `send_bot` returns the Vexa meeting id, saved in `Meeting.vexa_meeting_id`; the worker polls and fetches segments with `VexaClient.get_meeting_by_id` (`GET /transcripts/by-id/{id}`), so reusing a link cannot pick up an older recording. Rows without an id fall back to platform + code. The by-id response shape is assumed identical to the code lookup; not exercised against live Vexa.
- **CSRF**: one app-wide dependency (`auth.guard`) requires login for everything except `/login` and `/health`, and a matching `csrf_token` form field on every POST (403 otherwise). Anonymous sessions carry a token so the login form is protected too.
- **Untrusted text**: Jinja autoescape; notes rendered with markdown-it-py (`commonmark`, `html: False`, images disabled, links get `rel="noopener noreferrer nofollow"`; `javascript:` links are not rendered). CSP is `default-src 'none'` with only same-origin script/style/img, no inline code, so a miss in escaping still cannot run script or load remote images.
- **Statuses**: `bot_sent` = "Bot sent"; `processing` = step in plain words; `failed` shows `failure_reason`. The word "recording" is never shown from status. Meeting URLs (Zoom links carry a password) are never rendered or put in query strings; pages show platform + meeting id.
- **New meeting** (`POST /meetings`): `parse_meeting_url`, then a Postgres advisory lock around "no `bot_sent`/`processing` meeting" + `send_bot` + insert, so a double click cannot send two bots. Vexa failure saves nothing and shows a fixed message (no exception text).
- **Regenerate**: ready meetings only; `generate_notes` from the saved speaker transcript, in the request, no transcription. On failure the old notes are kept.
- **Cancel** (`POST /meetings/{id}/cancel`, button on `bot_sent` meetings only): calls `DELETE /bots/{platform}/{native_id}` (404 = no active bot, counted as stopped), then marks the meeting `failed` with "You cancelled this meeting before it was recorded." No OpenAI call. A Vexa error returns 502 and changes nothing.
- **Notices**: "Speaker names unavailable for part of this transcript." (`speakers_incomplete`) and "The bot left the meeting early or was removed. The notes may be incomplete." (ready meetings whose `completion_reason` is in `pipeline.REMOVAL_REASONS`). The home page warns when the worker heartbeat is missing or over 20 minutes old (raised from 5 on 2026-11-02 so a long transcription pass does not trigger it).
- **Health**: `/health` stays unauthenticated, runs `select 1`, and returns `ok` or `503 unavailable` with no detail.
- **Regenerate**: the form's buttons disable on submit (`data-disable-on-submit`, `app.js`); nginx allows 300 s on this route.
- **Retry** (`POST /meetings/{id}/retry`): failed meetings only; sets `processing`, keeps `step`, clears `failure_reason`, resets `started_polling_at`. Refused when `step == waiting` (nothing captured), when `failure_reason` is the no-speech constant (`pipeline.REASON_NO_SPEECH`: same audio, same result), or when the audio is deleted and no transcript was saved; the page says so.
- **Ids**: path ids use a custom converter matching 1-10 digits (longer input is a 404 before `int()` can raise on 4300+ digits, even when logged out); form ids go through `parse_id`, which rejects over 10 digits and anything above the Postgres integer range.
- **Templates / vocabulary**: list/add/edit and list/add/delete. Term rules match `app/transcribe.py` (no `<`, `>`, newlines; non-empty; at most 100 chars as in `app/notes.py`); duplicates give a clear error. Template instructions capped at 4000 chars (our choice).
- **Pages**: meta refresh every 30 s until `ready`/`failed`; copy buttons (`app/static/app.js`, same-origin, falls back to `execCommand`); small system-font CSS, dark mode via `prefers-color-scheme`.

## What's involved
`app/main.py` (`create_app`, headers, `/health`), `app/auth.py`, `alembic/versions/0002_app_state.py`, `app/models.py` (`AppState`), `app/vexa.py` (`get_meeting_by_id`), `app/pipeline.py` (`_lookup`), `app/web.py`, `app/templates/*.html`, `app/static/app.{css,js}`, `app/config.py` (`app_env`, `cookie_secure`), `pyproject.toml` (markdown-it-py; ruff B008 allowance for FastAPI), `Dockerfile` (`app` user), `compose.yaml` (`web`), `.env.example`, `tests/test_web.py`.

## Verification
`tests/test_web.py` (~80 tests, real Postgres, fake Vexa/OpenAI). Run locally against a scratch DB and checked at 375 px in the built-in browser: login, list, ready and failed meeting pages, templates, vocabulary all fit with no horizontal scroll. Not verified: copy buttons in a real browser clipboard, the Docker image/healthcheck (not built), HTTPS Secure cookie end to end.

## Operate / roll back
`docker compose up -d web` (serves on `127.0.0.1:8020`; put a TLS reverse proxy in front). `.env` needs `OWNER_PASSWORD` and `SESSION_SECRET`, or the service exits at start. Over plain http locally set `APP_ENV=development COOKIE_SECURE=false`. Run as `python -m uvicorn app.main:create_app --factory`. Run `alembic upgrade head` (the `migrate` service does) before starting `web`: it needs `app_state`. Roll back with `alembic downgrade 0001` plus reverting the commit.
