# SOP: W10 Integrations, part 1: the Slack webhook (migration 0032)

## What shipped
A team's owner or admin connects a Slack **incoming webhook**; after a meeting's notes are read, one message with the meeting's name (linked) and each new task with its owner is posted to that channel. API `GET/PUT/DELETE /api/integrations/slack`, the "Post tasks to Slack" row of Settings > Tasks, the privacy page's Slack line. PR: see the branch `feature/w10-slack`. The tracker is part 2 (migration 0033), waiting for Adebayo's pick (spec D11).

## Why
Spec section 12 and D11: Slack by a pasted webhook (no Slack app to build or get reviewed), then one tracker. One row per team (the pilot is capped at 10 accounts, so integrations belong to the team, not the person).

## How (decisions and rejected alternatives)
| Decision | Why |
|---|---|
| Webhook URL stored in the vault (`app/vault.py`), new purpose `integration`, owner `team:<id>:slack_webhook` | A blob copied to another team or kind does not open (test). Never returned, never logged; `GET` returns only state. |
| Address check on paste: `https`, host exactly `hooks.slack.com`, no port/userinfo/query/fragment, path `/services/T../B../token` | The host is a constant in `app/slack.py`, not a setting and not read from the stored value, so nothing stored can redirect a post. |
| Outbound call reuses the calendar fetch's SSRF defences (`app/ics_fetch.py`): resolve once, every address public, connect to that IP with the real SNI/Host, no redirects, `trust_env=False`, 3 s connect / 10 s total in a thread | Same threat class; httpx's INFO log of the request path (the secret) is silenced for that thread. Only the status code of the answer is read. |
| Text defanged then escaped: `titles.mail_line` (removes web addresses, defangs domains), then `& < >` escaped and `* _ ~ \` \|` dropped | `<!channel>`, `<@U..>` and `<url\|text>` cannot be produced from a transcript. |
| Connecting posts one test message first; a webhook Slack refuses is not stored (502 `slack_unreachable`) | Proves the address works and shows the person it landed in the right channel. |
| `integration_posts` row written **before** the call; partial unique index (team, kind, meeting) | At-most-once per meeting across worker retries; its rows in the last hour are the rate cap: 30 posts and 5 connect tries per team per hour. A capped meeting is skipped, not queued. |
| Post runs after the extraction's final commit, inside a catch-all (`integrations.notify_meeting`) | A Slack failure cannot touch notes, tasks or the extraction status. A failure sets `status=failing` and a fixed sentence (never Slack's own words) on the card. |
| Posts only for a meeting **shared with the team** (`meeting.shared_team_id == team`) | Found by the commit security review: teammates cannot see a private meeting's tasks (`tasks.visible`), so they must not reach the channel. Sharing after the first read does not post retroactively. |
| Posts only for non-quiet meetings still inside the mail window (same guard as the assignee mail) and only the first time a meeting is read | A notes rewrite does not post again; a backfill never posts. |
| Rejected: OAuth Slack app (review, scopes, a client secret to protect) and posting channel names (a webhook does not reveal its channel) | The card therefore shows "Slack connected" instead of the designer's `#channel` chip. |

## What's involved
`app/slack.py` (check, escape, message, outbound), `app/integrations.py` (connect, disconnect, notify), `app/api_integrations.py` (routes), `app/models.py` (`Integration`, `IntegrationPost`), `alembic/versions/0032_integrations.py` (`down_revision` 0026; whoever merges after 0027 to 0031 re-points it and `test_0032_follows_0026_and_is_the_only_head`), `app/workspace.py` (the hook), `app/vault.py` (purpose), web `settings-slack.tsx`, `settings-planned-sections.tsx`, `privacy-content.tsx` (no "Last updated" bump, no notice, per decision). No new `.env` variable and no nginx change: the vault uses `TOKEN_ENC_KEY`, already set in production; the server must be able to reach `hooks.slack.com:443`.

## Opus review (2026-11-06): no Critical, High or Medium
Fixed from its Low findings: per-team advisory lock around the count-then-insert of both caps; the row is re-read after the claim so a disconnect or reconnect in between stops or redirects the post; a webhook Slack called gone (404/410) is not tried again until reconnected; `link_names:false` sent explicitly. Accepted: a disconnect during an in-flight connect (up to 10 s) can be undone by it; the post runs inside the extraction worker and can delay it up to 10 s per meeting (capped at 30 posts per team per hour); re-point 0032 before merging (below).

## Operate / roll back
Revert the PR; `alembic downgrade 0026` drops both tables (stored addresses go with them). A team can disconnect itself at any time (the row, and the secret, are deleted). Rotating `TOKEN_ENC_KEY` follows the vault's existing steps; `integrations.key_version` is covered by them only if the re-encrypt script is extended (follow-up).
