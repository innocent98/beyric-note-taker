# SOP: W2 Tasks, screens (PR 2)

## What shipped
The Tasks screen (D5), the task drawer, the meeting page's Action items as task rows, "N tasks" on the meetings list, the Tasks item in the sidebar with its badge, and the two live switches of the Settings Tasks card. Frontend only; it builds on the backend of PR 1 (`docs/sop/2026-11-05-w2-tasks-backend.md`, `docs/fe-integration-guide-tasks.md`). Branch `feature/w2-tasks-ui`, PR against `feature/w2-tasks-api` (retargets to `main` when PR 1 merges). Not merged.

## Why
Tasks made by the worker are only useful if people can see, move and assign them. The design is full parity (Adebayo's rule): follow `docs/ui/` exactly, draw nothing it does not have, and draw nothing whose data does not exist yet.

## How
| Piece | Decision |
|---|---|
| Board | `components/app/tasks-view.tsx`: three columns, cards, filter chips, Group by, attention banner, drag and drop (HTML5, `PATCH status`, optimistic, put back with the API's words on refusal), New task (POST `{}` then the drawer opens on the blank task). The first page is the server render; a failed first load is "Could not load tasks" with Try again |
| Drawer | `task-drawer.tsx`, shared by the board and the meeting page. One PATCH per field. `can_update`, `can_edit`, `can_assign`, `can_claim`, `can_delete` from the API disable controls (a member who may only take a task is offered Unassigned and themselves). A 403 `team_forbidden` is shown in the panel. Quote only (no link) for an assignee of a private meeting's task (`meeting` null) |
| Meeting page | `NotesHtml` takes `actions`: when the meeting has tasks and the original (not a translation) is shown, the notes' own Action items part is replaced by `action-tasks.tsx` (summary and View board, rows with tick box, due day, owner or Needs owner). No tasks (pending, off, older meeting): the notes' bullets stay exactly as before |
| "Today" | `use-today.ts` (`useSyncExternalStore`): UTC on the server and first render, the person's zone (Settings, else the browser) after. Due labels are Today, Tomorrow, `Fri 6 Nov` as drawn; the Due select offers No due date and the next eight days (the drawn list is fixed sample days), plus the task's own date |
| Colours | no literals: six new tokens in `styles/tokens.css` (card and drawer shadows, drawer scrim, group rule, drop wash, strong warning line, chosen-segment shadow) |
| Mock and shots | `web/scripts/mock-api.mjs` serves the tasks routes in memory with the designer's sample tasks (the mock's own values, same shape as the captures); `parity-shots.mjs` gained the four task screens and `--now` (fixes the Next page's clock to the prototype's "today", 2 Nov 2026) |

## Designer gaps (for the designer)
No drawn state for: an empty board, tasks still being read ("Reading the action items..."), a failed read, an unverified task (no quote found; the API counts them in `attention.unverified`), a refused change, a delete confirmation (Delete task acts at once, as drawn), "Extract tasks from this meeting" for older meetings (the API exists), a task from a private meeting (shown as "From a meeting", quote only), a Due control for dates beyond the next week (a select of days is what is drawn), "Load older tasks" past 500.

## Verification
- 596 web tests pass (37 new: board, drawer, meeting rows, Settings card, date words), run on the captured bodies of `docs/fe-captures/tasks-w2/`. `npm run lint`, `npm run typecheck` clean; `tests/guards.test.ts` (no colour literals, event props only in client components) and `tests/routes.test.ts` pass with `/tasks`.
- Parity shots as above, built and served with the mock (`PLAYWRIGHT=... node scripts/parity-shots.mjs --design ... --next ... --only app-tasks,app-detail,app-meetings,app-settings --now 2026-11-02T10:00:00Z`).
- **Not verified:** against the real API in a browser (the mock, not FastAPI, answered); drag and drop on a touch screen; screen-reader use. The parity run shows a React hydration warning on `/tasks` only because the harness fixes the browser's clock while the server keeps the real one; it cannot happen with one clock.

No new settings. Reverting the PR removes the screens; the API keeps working.
