# SOP: mail upgrade (AI workspace phase W0.3)

## What shipped
The mail layer W2 (Tasks), W6 (Share) and W8 (reminders) will use: the designer's layout for every mail, attachments and reply-to on `Message`, **ids-only payloads** read at send time, a **suppression table** the sender honours, **send-time checks** (meeting still there, owner active, setting still on), per-recipient and per-day **caps**, and the first mail built on it, **"Notes ready"**. Branch `feature/w03-mail-upgrade`, PR to `main` (number in the PR list). Migration `0013`. Spike ML1: `docs/spike/resend-limits-2026-11-04.md`. No API route, no screen; the FE guides are unchanged (nothing a screen reads changed).

## Why
`app/mail.py` rendered a paragraph list and one button, held whatever a feature put in the payload, and had no way to stop mail to an address. The spec (section 10) needs shares that carry notes to people outside the app, which makes the mail layer an abuse and privacy surface: a title or name written by someone else must not change the page, notes must not sit in the outbox, a meeting deleted a minute ago must not be mailed, and a bounce or an opt-out must be remembered.

## How
| Piece | Decision |
|---|---|
| Modules | `app/mail_message.py` (`Message`, `Attachment`, address and line checks), `app/mail_layout.py` (blocks to HTML and text), `app/mail_templates.py` (what each mail says, the notes templates' registry), `app/mail.py` (mailers, outbox, suppression, caps, send loop). `mail.Message`, `mail.MailError`, `mail.render` and `mail.TEMPLATES` still exist |
| One source for both parts | A mail is a list of plain-text blocks (`Heading`, `Para`, `Label`, `Bullets`, `Quote`, `Button`, `Meta`). `render_html` escapes every string, `render_text` prints the same blocks, so the parts agree and nothing can hand the HTML renderer markup. The only `href` is a `Button`, and it must be an absolute http(s) URL (`check_url`). Deviations from the drawing (HTML "B" mark instead of inline SVG, system font stack) are in the module docstring |
| `Message` refuses | line breaks and control or bidi characters in subject, address, reply-to and header values; header names other than `List-Unsubscribe` and `List-Unsubscribe-Post`; an address that is not one plain address (no `<>`, comma, semicolon, quote, space); attachments over `MAX_ATTACHMENT_BYTES` (10 MB together), more than 3, or not PDF, Word or text; its `repr` leaves out the body and file bytes. So a mailer never sees a malformed message |
| Two kinds of template | **Link templates** (verify, reset, already registered, waitlist invite): payload holds the link, **account mail**: never held for caps, stopped only by a bounce or complaint, scrubbed within the hour as before. **Notes templates** (`notes_ready` now; share, tasks, reminders later): `enqueue` accepts **integers only** in the payload (`ValueError` otherwise), the text is read at send time, the hold is 24 hours, caps apply. A done notes row **keeps** its ids-only payload (no secret in it; link rows are still scrubbed), which is what lets a unique index (`uq_mail_outbox_notes_ready_meeting`, partial on `notes_ready`) allow one Notes-ready mail per meeting for good, however many workers or retries; `queue_notes_ready` queues inside a savepoint and returns None for the loser of a race A later phase adds one with `@notes_template("name")` and returns a `Message` or a `Skip("reason")` |
| Send-time checks (in order) | valid address (else `failed`, "invalid address") then suppression then daily quota then the template's own guards (`ready_meeting`: meeting exists, is ready with notes, owner `active`; `notes_ready` also: the row's address is still the owner's, `user_settings.notify_email` still on) then the recipient cap (moved after the guards by the pre-launch part 1, so the true reason wins and the owner is told only for a mail that would have gone) then send. Any guard that says no leaves the row `skipped` with a reason slug (`suppressed`, `recipient_cap`, `meeting_gone`, `owner_inactive`, `not_ready`, `recipient_changed`, `opted_out`) and an empty payload. `skipped` is a new status (`ck_mail_outbox_status`), not a failure: the admin's mail-failures list does not show it |
| Suppression | `mail_suppressions(email_hash pk, reason)`, hash of the lower-cased address (`usage.email_hash`), reasons `bounce`, `complaint`, `unsubscribed`. A bounce or complaint stops **all** mail to the address, sign-in mail included (a mailbox that rejects us or reported us is not helped by more mail). An unsubscribe stops every mail **except link/account mail** (a person who opted out of shared notes can still reset a password). `suppress` keeps the first reason, except that `unsubscribed` is upgraded to `bounce` or `complaint` (never the reverse), so a bounce reported later does stop sign-in mail. Not deleted when an account is deleted. Checked at SEND time, so a mail queued before the bounce is stopped |
| Caps | `MAIL_DAILY_CAP` (default 80, 0 = off): once that many mails have gone since 00:00 UTC (every kind counts, as Resend counts) notes mail is **held**, still `pending`, no attempt used, and goes after midnight UTC; link mail is never held. `MAIL_RECIPIENT_DAILY_CAP` (default 5, 0 = off): notes mails one address gets per 24 hours, the rest are `skipped`. Both optional, both in `.env.example`; sized from spike ML1. The per-account "20 mails a day" of the share spec belongs to W6 (the outbox has no sender column) |
| Notes ready | Queued in the same commit as the notes (`pipeline._step_notes`), best effort inside a savepoint so it can never fail or roll back the meeting; only when a provider is configured; once per meeting; not for an inactive owner or one with `notify_email` off. Carries Summary, Decisions, Action items and Open questions (the headings the default template writes; another template's first section stands in), abridged to 600 characters at a sentence, 6 items of 200, "and N more in the full notes"; "View full notes" is a plain link to `/meetings/{id}` (needs sign-in, no token); "The note taker left early, so these notes may be incomplete." when Vexa's `completion_reason` is `evicted` or `max_bot_time_exceeded` (a test pins that set to `pipeline.REMOVAL_REASONS`). Regenerating notes never mails |
| Batch order | Link mail is loaded **first and on its own** (`pending_ids`), and notes mail is not loaded at all once the day's quota is spent, so notes mail held for the quota (pending up to 24 h) can never fill the 100-row batch and starve a verification or reset mail until the sweep fails it |
| Unexpected errors | A builder reads the database. An exception in one counts as an attempt, keeps its type name only, and the row is failed after the last retry: one poison row cannot hold the queue |
| Rejected | A `payload` copy of the notes that the sender then scrubs (the notes would exist in backups for the hour); a sender-side allow list of hosts for links (no link is built from user text at all); one mail to many `to` addresses (each recipient must be checked, and none may see another's address); a Resend webhook now (new unauthenticated route and a signing secret: its own phase) |

## Operate / roll back
- **Server steps before merge: none.** `MAIL_DAILY_CAP` and `MAIL_RECIPIENT_DAILY_CAP` are optional with safe defaults. After merge the migration runs on deploy.
- On Resend's **Pro** plan set `MAIL_DAILY_CAP=0` (no daily limit there).
- Stop an address now: `docker compose exec web python scripts/suppress_email.py add someone@example.com complaint`. Allow it again: `... remove ...`. Look at one: `... check ...`.
- A mail that never arrived: its `mail_outbox` row says why (`skipped` with a reason, `failed` with `HTTP n`); `last_error` is a code, never text from the meeting.
- Roll back: revert the PR; `alembic downgrade 0012` is safe (skipped rows become failed, the suppression table is dropped, so suppressions are lost: export the hashes first if any matter).
