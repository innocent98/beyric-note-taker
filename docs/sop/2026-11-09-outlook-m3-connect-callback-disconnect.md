# SOP: Outlook phase O, M3, connect, callback and disconnect for Microsoft

## What shipped
The Microsoft side of the calendar connect, on the shared `/api/calendar/{provider}/...` routes (spec `docs/superpowers/specs/2026-11-04-outlook-oauth-design.md` sections 4.1, 4.4 to 4.6, 6.3, 8.1): `app/microsoft_connect.py` (start, callback checks, probe, store), `app/graph_http.py` (the one place a Graph URL is built), the `microsoft` row of the provider registry, the flag `MICROSOFT_CALENDAR_ENABLED`, and disconnect with no revoke. Branch `feature/outlook-m3-connect`, **stacked on `feature/outlook-m2-oauth-client` (PR #150) with `feature/outlook-m5-graph-events` (PR #151) merged in**; retarget to `main` once both have merged. **No migration** (0027 already has every column). Dark: while the flag is off, `connect` and `callback` answer 404 `calendar_unavailable` for everyone; no Outlook wording reaches any screen (the UI is M6).

## Why
Same seven checks as Google's connect, with Microsoft's differences: identity is tenant plus object id, the consent can be refused by tenant rules, an account can be real yet have no mailbox (so it is probed before anything is stored), and there is no revoke call, so disconnect only forgets locally and says so.

## How
| Piece | Decision |
|---|---|
| Routes | The `{provider}` routes branch on `microsoft`. `POST connect` (features must be exactly `["calendar"]`, else 422 `invalid_features`), `GET callback`, `POST disconnect`. Flow cookie `calendar_flow_ms`, path `/api/calendar/microsoft` (registry values). Google's code path is unchanged |
| Flag | `PROVIDERS["microsoft"].enabled` = `CALENDAR_ENABLED` and `MICROSOFT_CALENDAR_ENABLED` and a full client. While false: `connect` and `callback` 404 `calendar_unavailable`, no source is built, nothing Microsoft is contacted. **Disconnect still works** (and with nothing connected is a no-op): deleting a person's data never depends on a flag. The state, settings and recurring routes now need `CALENDAR_ENABLED` and (Google configured **or** Microsoft on) |
| Callback order | state (Microsoft flow, single use, deleted whatever the answer) → signed in (else `/login?error=microsoft_failed`) → same user (`wrong_account`) → flow cookie → Microsoft `error` (`access_denied` is `microsoft_denied`, any other `microsoft_failed`; `error_description` is never read) → code present → redeem and check the ID token (`microsoft_failed`, `tenant_not_allowed`) → `Calendars.Read` granted **and** a refresh token (else `scope_missing`) → probe → label → store. Flow isolation: a Google state at this callback and a Microsoft state at the Google callback both fail and are used up |
| Probe (4.5) | `GET /v1.0/me/calendarView` for the next hour, `$top=1`, with the new access token: 200 stores; 404 or a mailbox error code is `no_mailbox`; 401 or 403 `scope_missing`; anything else (429, 5xx, timeout) `microsoft_failed`. The mailbox codes (`MailboxNotEnabledForRESTAPI` and two siblings) are documented by experience, not by Microsoft's pages |
| Label | `GET /me` `mail`, else `userPrincipalName`, else the ID token's `preferred_username`, else its name: a **label only**, lower-cased and checked for one `@`; a failing `/me` costs only the label. Identity is `tenant_id` plus `account_subject` (the `oid`, else `sub`) |
| Domains (review focus 8) | `GET /organization` `verifiedDomains` is read **only** for a work account **and** only if `MICROSOFT_ORGANIZER_DOMAIN_TRUST=true` (default false). An organiser address inside the tenant's domain is only as trustworthy as Exchange Online's anti-spoofing, which the M0 run has not confirmed, so by default `tenant_domains` stays empty, `organizer_same_org` is false and an unanswered colleague invite waits for "accept" (the safe direction). Turn it on only after M0 S4/S5 |
| One calendar (6.3) | Start refuses with 409 `calendar_already_connected` when another provider's calendar is live; the callback re-checks **under the user's own row lock** (the lock Google's store takes), so two tabs finishing two providers queue and exactly one wins (a threaded test holds the lock open, commits a Google connection, and the Outlook store then refuses with `already_connected`). A Meet-only Google row and a `disconnected` row never block |
| Reconnect | One Microsoft row per user, updated in place. A different identity over a working connection is refused (`different_account`); over a dead (`needs_reconnect`) one it replaces it and drops the old identity's events and unstarted joins (the Google rule); a join already live keeps going. The same email with another `oid` is another identity |
| Disconnect | Deletes exactly what C4 deletes (events, every scheduled join in every state, `calendar.*` notifications), keeps what C4 keeps (meetings, usage, settings), empties the row including `tenant_id`, `account_kind`, `tenant_domains`, commits, **then** runs the `ON_DISCONNECT` hooks (nothing is sent to Microsoft). Answer: `{"status":"disconnected","revoked":false,"reason":"provider_has_no_revoke"}` when a token existed; the repeat or an empty disconnect gives `{"status":"disconnected","revoked":true}`. `reason` is **absent** (not null) for Google (`response_model_exclude_none`), so Google's answer keeps its exact shape |
| Registry row | `granted_features` = `calendar` iff `Calendars.Read` is granted (exact, after stripping `https://graph.microsoft.com/`, any case); `parse_event` = `graph_events.parse_event` with `tenant_domains` for a work connection only; `make_source` raises `NotImplementedError` until M4 (nothing builds a source while the flag is off) |
| Graph URLs | `app/graph_http.py`: `GRAPH_BASE = https://graph.microsoft.com/v1.0`, `graph_url(path)` for paths the code writes, `under_graph_base(url)` for a `nextLink` (M4), and a single `get()` that refuses any other URL **before** a request so the `Authorization` header cannot leave; redirects off, no proxy from the environment |
| Rejected | Calling Graph from the probe with a host or path taken from an answer; reading `error_description` to tell "no mailbox" from "blocked"; matching a reconnect on the email; trusting `tenant_domains` by default; a per-provider disconnect route |

## Verification
- Tests first (all against the real client over a fake Microsoft, `tests/fakes/microsoft.py`): URL parameters and PKCE against the stored verifier; flow row (provider, hash, 10 minutes); the cookie's flags and path; `return_to` hostile values; 422 for `meet`; 404 for flag off, features off, no client id, no secret (and nothing contacted); 503 without a key; a personal and a work connect; vault purpose (not openable as a Google blob or by another user); the exact redemption and probe requests (method, URL, body, bearer, hosts contacted); label fallbacks; domains (off by default, on, every failure shape); allow-list and the `consumers`-with-work-tenant refusal; unknown, replayed and expired state; Google state at the Microsoft callback and the reverse; signed-out, another user (login CSRF), missing and Google-named cookies; every callback error; bad nonce, audience, issuer; token endpoint down; three scope shortfalls; ten probe outcomes; the 409 rule in both directions, in every live state, and under the row lock; reconnect, different identity (also same email), dead-connection replacement; the full C4 delete and keep lists, idempotence, hooks after the commit, nothing sent to Microsoft; and a log test over success and every failure path with sentinel strings (the app's own log lines only).
- Suites run before the push: `ruff check .`, `ruff format --check .`, `pytest --collect-only -q tests`, the M2/M3/M5 files, `test_calendar_*`, `test_gcal_*`, `test_join_runner`, `test_accounts`, `test_edge`, `test_migrations`, `test_vault`, `test_api`; web `npm run gen:api`, `typecheck`, `lint`, `vitest`. OpenAPI regenerated with `scripts/export_openapi.py` (only the description text, `DisconnectOut.reason` and the 422 on connect changed).
- **Not verified live:** nothing here has talked to Microsoft; the fake follows the documented shapes. `no_mailbox` and the consent-denied redirects were not seen from a real account.

## Operate / roll back
**Server steps before merge: none** while the flag stays false. At switch-on (not part of this PR): set `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, `MICROSOFT_AUTHORITY=consumers`, `MICROSOFT_CALENDAR_ENABLED=true` (optionally `MICROSOFT_ALLOWED_TENANTS`, `MICROSOFT_SECRET_EXPIRES_ON`, `MICROSOFT_ORGANIZER_DOMAIN_TRUST`), recreate `web` and `scheduler`, **and M4 must be deployed first** (without it `make_source` raises when the scheduler builds its sources). Roll back by reverting the PR: a Microsoft row left behind is inert (no migration, nothing reads it without the flag).
